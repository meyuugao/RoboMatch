# RoboMatch - итоговая сводка

Что построено, почему так и с какими допущениями. Коротко и по фактам:
каждое утверждение проверяемо кодом, тестами или живым прогоном.
Детали - по ссылкам в конце.

## 1. Что реализовано

| Модуль | Статус | Суть |
|---|---|---|
| Каталог решений | **полностью** | 187 решений из таблицы организатора; иерархия (отрасль → тип → процесс → тип/подтип); поиск с индексом GIN, 10 фильтров, сортировка, пагинация; сравнение до 10 решений; карточка с ТТХ (EAV) и провенансом каждого значения; импорт таблицы и обновление по запросу |
| Параметры объекта | **полностью** | 3 типа объектов (склад 45 / аэропорт 41 / медицина 59 параметров); формы с валидацией и дефолтами датасета; импорт Excel/CSV по скачиваемому шаблону; вложения; фиксированные и производные параметры |
| Подбор решений | **полностью** | 8 проверок ТТХ; статусы «годится / требует проверки / исключено» с причинами; ранжирование с весами по типу объекта; объяснимость - вклад каждого критерия в Score; ручное добавление с причиной |
| Экономика | **полностью** (склад) | 3 сценария (текущий процесс / покупка / RaaS); CAPEX (6 статей + резерв), OPEX, ΔOPEX, годовой эффект, окупаемость с интерпретацией, ROI, TCO; чувствительность 3 параметра × 5 шагов; изменяемые допущения; ручная корректировка (append-only журнал); история с версиями данных (SHA-256) |
| Имитация 2D | **частично** | Детерминированная аналитическая модель (не дискретно-событийная): 6 KPI, сверка с расчётом экономики; SVG-схема склада (5 зон, 20 точек операций, маршрут), анимация, скорость 0,5–5×; сохранение схемы; светлая/тёмная темы; без редактора схемы и загрузки планировки |
| Экспорт отчётов | **полностью** | PDF (10 разделов, оглавление, встроенная 2D-схема, выбор темы), Excel (7 листов), CSV (UTF-8 BOM, «;»); пометка «предварительная оценка»; история выгрузок; примеры - `docs/examples/` |
| Управление (админ) | **частично** | CRUD решений и ТТХ с провенансом; 7 справочников; массовое удаление со сводкой; импорт таблицы каталога (идемпотентный, журнал); обновление по запросу. Отложено: правка дефолтов параметров и нормативов в UI |
| Гостевой демо-расчёт | **частично** | Каталог и сравнение без входа; демо-расчёт трёх сценариев на /demo (в памяти, без записи в БД) на демо-наборе «Склад». Демо-наборы аэропорта и медицины не подготовлены |

Сквозное: аутентификация JWT (BCrypt-12, роли, изоляция проектов - 404
на чужой), Swagger UI (63 операции, 71 схема), тёмная тема, русскоязычный
UI от 1366×768, полный пользовательский путь из 8 шагов, docker-compose
из 5 сервисов одной командой.

Качество: 563 автотеста backend; e2e-верификаторы живого стека
(~730 проверок суммарно плюс 165 свереных полей эталона: экономика -
259 формул против эталона без расхождений, интерфейсы, экспорт, схема
имитации - 0 перекрытий подписей на 4 разрешениях × 2 темы); seed и импорт каталога
идемпотентны.

## 2. Что пропущено (вне объёма)

- Автоматический парсинг каталога и плановое автообновление - вместо
  них обновление по запросу администратора.
- Интеграции WMS/ERP/1С, проверка по государственным реестрам.
- 3D-визуализация; дискретно-событийная имитация с топологией.
- ML и оптимизация состава парка.
- Полный расчёт/имитация/экспорт для аэропорта и медицины (параметры
  и подбор доступны, расчёт - только склад).
- Роль вендора; восстановление пароля и email; расширенная
  чувствительность (более 3 параметров); моделирование замен
  выкупленного RaaS-парка.

Полный перечень с обоснованиями - `docs/mvp_scope.md` и журнал
`docs/backlog/closed_questions.md`.

## 3. Что работает и что не доработано

**Работает стабильно:** полный путь пользователя (гость → демо-расчёт;
пользователь → все 8 шагов до отчёта; админ → ведение каталога);
экономика сходится с эталоном формула-в-формулу; отчёты во всех трёх
форматах согласованы 1:1; имитация укладывается в ~200 мс при пороге
60 с; повторные запуски seed/импорта не создают дублей.

**Не доработано (осознанные границы, влияющие на интерпретацию
результатов):**

- Нагрузочное тестирование на 50 пользователей не проводилось;
  расчёт экономики синхронный (в очередь не перенесён).
- Контур безопасности рассчитан на демо, не на прод: access-only JWT
  без refresh, logout без серверной инвалидации, без rate limit
  (смягчение - bcrypt cost 12), TLS не терминируется (штатно для
  локального демо).
- Имитация - «снимок» KPI аналитической модели, а не событийное
  движение; калибровка sim-коэффициентов под конкретный объект не
  выполнялась (дефолты дают консервативное предупреждение о зазоре
  с P_effective).
- Экономика сравнивает сценарии по консервативному baseline (ФОТ
  целевых групп без прочих текущих расходов) - эффект роботизации
  выглядит верхне-оценочно.
- ТТХ из открытых источников дозаполнены только для 10 приоритетных
  решений; у остальных - данные таблицы организатора как есть.
- Контрольный прогон docker compose на реальном Docker-демоне не
  выполнялся (стек верифицирован нативно; чек-лист - в README).

## 4. Ключевые допущения

Полный реестр с обоснованиями - `docs/assumptions.md`. Влияющие на
результат больше всего:

1. **Worst-case дефолты** (без обследования объекта): паллета 1500 кг,
   штучная единица 20 кг, потолок 5 м, проезды 2,5/1,5 м, мощность
   100 кВт, пол 5000 кг/точку, шум 25 дБА, точность 1 мм.
2. **K_load = 0,75** (0,70–0,85) - фактическая загрузка робота от
   номинала; **K_reserve = 0,15** - резерв парка от пиковой нагрузки.
3. **Baseline OPEX = только ФОТ целевых групп** (отборщики + операторы
   погрузчиков, ×12 месяцев, ×1,302 начислений) - прочие текущие
   расходы текущего процесса не учитываются.
4. **RaaS:** ставка 2 %/мес (1,5–3 %), контракт 3 года, без выкупа
   (выкуп опционален). Без выкупа платежи идут весь горизонт; при
   выкупе - годы контракта (min(контракт, горизонт)) плюс разовый
   выкуп по остаточной стоимости в CAPEX; прочий OPEX - весь
   горизонт.
5. **Горизонт расчёта - не менее 5 лет** (меньше блокируется: TCO
   на горизонте).
6. **sim-коэффициенты имитации:** средний маршрут 60 м, погрузка/
   разгрузка 40 с, скорость 1,5 м/с - влияют только на KPI имитации,
   не на экономику.
7. **Маппинг «тип объекта → отрасли»** (7 связей) задан вручную -
  определяет пул решений для подбора.
8. **Тариф электроэнергии 7,0 руб./кВт·ч**; мощность робота при
   отсутствии данных - консервативно по мощности зарядки.
9. **Цены каталога** - рубли с НДС, без доставки, пусконаладки и
   интеграции.
10. **CAPEX = цены парка × ~1,66**: инфраструктура 10 %, ПО 15 %,
    интеграция 15 %, пусконаладка 7,5 %, обучение 3 %, резерв 10 %
    от суммы статей; амортизация линейная.
11. **Эксплуатационный персонал роботов - 0** по умолчанию; персонал
    вне контура роботизации не сокращается.
