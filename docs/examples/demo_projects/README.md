# Демо-проекты из тестовых фикстур

Три демо-проекта владелец — демо-аккаунт `user` (пароль `useruser`),
создаются seed-ом (`scripts/seed/repositories/test_projects_repo.py`)
и показывают УСПЕШНОЕ использование платформы на решениях ТЕСТОВЫХ
ФИКССТУР (`docs/test-fixtures/full_catalog_a.xlsx` + `full_catalog_b.csv`;
импорт — только через админку, в seed фикстуры не попадают).

## Инварианты всех трёх проектов

- подбор находит решения фикстур со статусом **fit** (нет исключений
  по грузоподъёмности, габаритам, мощности, шуму, точности);
- `selectedRobots == requiredRobots` → `underpowered = false`,
  `overpowered = false`;
- `Effect_year > 0`, ROI ≤ 500 % (сноска A10 не срабатывает),
  Payback ≤ 5 лет;
- состав сценариев purchase/raas — ТОЛЬКО решения фикстур
  («РТ-*» / «АТ-*»).

## Калибровка параметров (предрасчёт)

Диапазоны метаданных склада ограничивают проектирование:
pickers_count ≥ 15, forklift_operators_count ≥ 5, зарплаты ≥ 70/80 тыс.
→ минимальный базовый ФОТ контура ≈ 22,7 млн руб./год
((15×70 000 + 5×80 000) × 12 × 1,302). Поэтому «разумная» экономика
(ROI ≤ 500 % = Effect_year ≤ CAPEX) требует парк с CAPEX того же
порядка — параметры объёмов подобраны так, что требуемый парк
(§2.1) совпадает с составом:

- Оптимальный: 3800 паллет/сутки ÷ 22 ч × 1,5 = 259,1 оп/ч →
  ceil(259,1 × 1,15 / 67,5) = 5;
- Пиковая: 3000 ÷ 22 × 2,5 = 341,1 оп/ч → ceil(341,1 × 1,15 / 67,5) = 6;
- Умеренный: 1500 ÷ 22 × 1,5 = 102,3 оп/ч, P_effective = 25 × 0,75 =
  18,75 → ceil(102,3 × 1,15 / 18,75) = 7.

Габаритные worst-case ослаблены до реалистичных (в отличие от E2E
worst-case: rack_aisle 2,2–2,4 м против 1,5; ceiling 5–5,5 м против
3; floor_load 2000–3500 кг) — под реальные ТТХ фикстур (ширина до
1250 мм, высота до 2400, масса до 1350 кг).

## Воспроизведение

```bash
# 1. стек: docker compose up (PG + backend + frontend + seed)
#    или локально: PostgreSQL + backend + npm run dev; seed выполнен
# 2. импорт фикстур через админку (UI /admin/catalog/import или API):
#    POST /api/admin/catalog/import — full_catalog_a.xlsx, full_catalog_b.csv
# 3. повторный seed — доделывает составы демо-проектов:
DATABASE_URL=... python scripts/seed/run.py      # вставок 0 (идемпотентно)
# 4. полный путь и сверка с эталоном:
BACKEND_URL=http://localhost:8080 python3 scripts/verify_economics_new.py
#    (импорт фикстур + подбор + расчёт ×3 + сравнение + инварианты; 47/47)
# 5. скриншоты:
FRONTEND_URL=http://localhost:3100 python3 scripts/shoot_demo_projects.py
```

Скриншоты ниже — страницы экономики и сравнения сценариев каждого
проекта (1366×900, светлая тема): `optimal-{economics,comparison}.png`,
`peak-{economics,comparison}.png`, `moderate-{economics,comparison}.png`.
