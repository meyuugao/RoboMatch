# Границы MVP

## Что такое MVP в этом проекте

Платформа предынвестиционной оценки роботизации.
MVP — обязательный минимум, при котором главный сценарий проходит
от начала до конца: от выбора объекта до выгрузки отчёта на одном
типе объекта (склад), с возможностью расширения на другие. MVP не
покрывает дополнительные преимущества и план развития (автопарсинг,
автообновление, интеграции, 3D, ML). Цель — готовый к демонстрации
реальному клиенту продукт, который можно пилотировать,
а не production-ready система.

## Входит в MVP (полностью реализуем)

### Пользовательские сценарии
Полные сценарии — в `requirements/roles.md`, `requirements/user-flow.md`.

Реализуем полностью:
- Гость: каталог, выбор объекта, демо-расчёт без сохранения
  коммерчески чувствительных данных
- Пользователь: CRUD проектов, ручной ввод параметров и импорт,
  подбор, сравнение решений (базовый + не менее двух роботизированных),
  анализ CAPEX, OPEX, эффекта, окупаемости, ROI и рисков,
  2D-имитация, сохранение, экспорт
- Админ: управление каталогом, справочниками, параметрами,
  нормативами, источниками

Реализуем частично:
- Аэропорт и медицина: выбор объекта, параметры, решения —
  без полного расчёта и имитации

### Целевой путь
Все 8 шагов — в `requirements/user-flow.md`.
В MVP реализуем все 8 шагов для склада.
Для аэропорта и медицины — шаги 1–3.

### Объекты
- Склад — полностью: ручной ввод через формы, импорт по шаблону
  Excel/CSV, проверка корректности типов, единиц, обязательных полей
  и диапазонов, значения по умолчанию, расчёт, имитация
- Аэропорт — выбор, параметры, решения
- Медицина — выбор, параметры, решения

### Каталог
- Иерархия: отрасль → тип объекта → процесс → тип решения → продукт
- Фильтры, поиск, сортировка, сравнение
- Источник, дата, признак подтверждённости
- Импорт из файла организатора
- Ручное добавление и редактирование через админку
- Обновление каталога по запросу администратора;
  плановое автоматическое обновление — вне MVP (преимущество)
- Расширение: до 5–10 решений на тип объекта, с указанием источника

### Подбор
- Правила фильтрации по ТТХ и инфраструктуре
- Объяснение включения и исключения
- Ранжирование с видимыми критериями
- Ручное добавление с предупреждением
- При отсутствии ТТХ — явные допущения и границы применимости
- Правила исключения — в `docs/selection_algorithm.md`

### Экономика
- Количество роботов, CAPEX, OPEX, TCO, ROI, окупаемость, годовой эффект
- Не менее трёх сценариев: базовый без роботизации + покупка + RaaS
- Амортизация CAPEX (метод и срок — в `docs/assumptions.md`)
- Изменение ключевых допущений пользователем: стоимость персонала,
  режим работы, производительность, стоимость оборудования,
  стоимость обслуживания, коэффициент загрузки, горизонт расчёта
- Ручная корректировка расчётных значений с фиксацией изменения
- Чувствительность к 3 параметрам
- Формулы, единицы, источники и допущения видны пользователю и в отчёте
- Итоговая таблица/дашборд сравнения сценариев
- Интерпретация окупаемости: до 3 лет, 3–5, более 5
- Цены с НДС, без доставки, пусконаладки и интеграции
  (если иное не указано организатором)
- RaaS: структура платежей, распределение CAPEX/OPEX, срок контракта —
  в `docs/assumptions.md`

### Имитация и визуализация
- 2D-схема: зоны, маршруты, роботы, точки зарядки
- KPI, связанные с расчётом
- Запуск, остановка, перезапуск, скорость, выбор сценария
- 2D-имитация: SVG-схема, 6 KPI, управление запуском, сверка
  с экономикой, сохранение схемы
- Модель — детерминированная аналитическая, без
  дискретно-событийного движения роботов
- 3D — вне MVP

### Экспорт

- PDF-отчёт: параметры объекта, выбранные решения, состав оборудования,
  экономика, ограничения, источники данных, дата расчёта
- Excel/CSV с расчётными таблицами
- Пометка «предварительная оценка, требует верификации»
- Страница выгрузки с историей (скачивание/удаление)
- Генерация с индикатором
- Файлы удаляются вместе с проектом
- Пример отчёта — docs/examples/

### Админка
- CRUD решений, справочников, параметров, нормативов, источников:
  - решения (карточка) — CRUD за `/api/admin/**` + ручной ввод с
    провенансом «вручную — требует проверки»;
  - справочники — 7 шт. (отрасли, процессы, производители, регионы,
    типы/подтипы решений, типы характеристик) — CRUD с FK-запретами
    удаления;
  - ТТХ решений (EAV) — upsert/удаление с типобезопасностью и
    провенансом manual/open_source;
  - параметры и нормативы — чтение/правка дефолтов отложены
    (снимки расчётов неизменяемы); источники данных — провенанс-поля
    самих сущностей (отдельной сущности нет);
- Загрузка таблицы решений от организатора: импорт CSV/XLSX
  (идемпотентность), история загрузок, обновление по запросу.

### Архитектура и инфраструктура
- Разделение клиента и сервера: Next.js + Spring Boot + PostgreSQL
- Расширяемость: новые отрасли, объекты, решения, параметры,
  расчётные модули — без правки ядра системы
- Docker + docker-compose, один `up` поднимает всё
- Seed-данные: каталог, склад, аэропорт, медицина
- Работа на заранее загруженных данных, без зависимости от внешних источников
- OpenAPI-спецификация; все реализованные API документированы
- Работа на ноутбуке пользователя, без спецоборудования

### Производительность и UI
- 50 одновременных пользователей
- Расчёт экономики ≤ 10 секунд
- Запуск/пересчёт модели ≤ 60 секунд, статус выполнения
- Обработка ошибок загрузки без потери проекта
- Ключевой сценарий выполняется без обращения к инструкции
- Русский интерфейс, единицы измерения, подсказки, примеры
- Ошибки с понятным языком и способом исправления
- Разрешение от 1366×768

### Безопасность и данные
- Разграничение доступа по ролям
- Пароли только в хеше
- Изоляция проектов разных пользователей
- Передача по защищённому протоколу при размещении в сети
- Удаление проекта вместе с загруженными файлами
- Никаких реальных ПДн в демо-данных и seed
- Воспроизведение расчёта с версией исходных данных и модели
- Логирование без чувствительных данных

## Не входит в MVP

- Расширенная чувствительность: больше 3 параметров и произвольные шаги
- Моделирование замен выкупленного RaaS-парка после исчерпания остаточного
  срока службы (в сценарии покупки замены учитываются)
- Автоматический парсинг каталога
- Плановое автообновление каталога
- Интеграции с WMS, ERP, 1C, госреестрами
- 3D-визуализация
- ML и оптимизация
- Роль вендора (опционально)
- Расчёт господдержки
- Проверка по государственным реестрам
- Полный расчёт и имитация для аэропорта и медицины

## Обоснование границ

- Приоритет — пройти полный путь на складе, а не распылиться на три объекта
- Аэропорт и медицина — на уровне выбора и параметров, для демонстрации расширяемости
- Всё вне MVP — план развития.
- Вне MVP — только если не ломает основной путь

## Что показать на демо

1. Гость: каталог, демо-расчёт
2. Пользователь: создаёт проект склада, вводит параметры, импортирует
3. Подбор: список решений с объяснением
4. Сравнение: базовый + покупка + RaaS
5. Экономика: CAPEX, OPEX, ROI, окупаемость
6. Чувствительность: меняем 3 параметра
7. 2D: запускаем модель
8. Экспорт: PDF + Excel
9. Админка: вход admin/adminadmin, CRUD решения и справочника,
   загрузка таблицы организатора с summary и повторная загрузка —
   0 изменений (идемпотентность)
