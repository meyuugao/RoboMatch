# Тестовые фикстуры каталога

Два независимых набора решений для проверок импорта и E2E — созданы
командой, организатор не участвовал. Каждый набор небольшой (4 решения),
но полностью заполненный: все 27 характеристик `characteristic_type`
(assumptions.md §14) у каждого решения.

| Файл                  | Формат             | Решения  | Вендор           | Отрасль               |
|-----------------------|--------------------|----------|------------------|-----------------------|
| `full_catalog_a.xlsx` | Excel (POI)        | 4 «РТ-*» | ООО Роботест     | Транспорт и логистика |
| `full_catalog_b.csv`  | CSV «;», UTF-8 BOM | 4 «АТ-*» | ООО Автоном Тест | Торговля и услуги     |

Наборы не пересекаются по `external_id` (стабильные UUID
`aaaa0001…0004` / `bbbb0001…0004`). Файлы детерминированы:
`python3 scripts/gen_test_fixtures.py` восстанавливает их байт-в-байт.

## Расширенный формат импорта

Файлы совместимы с `POST /api/admin/catalog/import` и используют
расширение формата таблицы организатора:

- **15 базовых колонок** `docs/source/catalog_export_v4.csv` —
  обязательны (как у организатора);
- **27 колонок ТТХ** — заголовок = код из `characteristic_type`
  (`payload_kg`, `mass_kg`, `length_mm`, `width_mm`, `height_mm`,
  `positioning_accuracy_mm`, `speed_m_s`, `charging_power_kw`,
  `noise_level_dba`, `autonomy_h`, `productivity`,
  `operating_conditions`, `lifecycle_years`, `floor_coverage_req`,
  `communication_req`, `integration_req`, `service_req`,
  `software_cost`, `implementation_cost`, `maintenance_cost`,
  `acquisition_model`, `limitations`, `country_of_origin`,
  `navigation_type`, `source`, `source_date`,
  `confirmation_status`). Допустим префикс «char:» (`char:payload_kg`);
  неизвестный непустой заголовок отклоняется ошибкой формата — опечатка
  не теряет данные молча.

Семантика колонок ТТХ (порт правил EAV, `AdminCharacteristicService`):

- значение типобезопасно по `data_type` (число/текст/да-нет/дата ISO);
- попадает в `solution_characteristic` с провенансом
  `source_kind='organizer_catalog'`;
- 9 зеркальных ТТХ-колонок `solution` синхронизируются (data_model.md §5.8);
- провенанс всех ТТХ решения — из колонок того же файла: `source`
  (URL-источник фикстуры), `source_date` (ISO-дата),
  `confirmation_status` («подтверждено» → `is_confirmed=true`;
  иначе — false, assumptions.md §7);
- пустая ячейка не создаёт строку и не затирает существующее значение;
- файл без колонок ТТХ (обычная таблица организатора) работает как
  раньше — характеристики не затрагиваются.

Идемпотентность: повторный импорт того же файла — 0 добавлений и
0 обновлений (счётчик `characteristics` показывает 108 = 4 x 27
пропущенных).

## Назначение

Фикстуры закрывают полный путь пользователя без организаторского
каталога: подбор (fit/исключения с причинами) → экономика →
имитация (6 KPI) → экспорт (PDF/SVG). ТТХ реалистичные, но подобраны
так, что профиль склада из 7 параметров (паллета 300 кг, пол 2500 кг,
проходы 2,2/2,5 м, шум 70 дБА, точность 20 мм) даёт 5 fit-решений и
3 исключённых (грузоподъёмность) — видно обе ветки подбора.

Новые E2E-проекты (проверки/демо)
создаются на решениях только из этих фикстур, а не из каталога
организатора.

## Как импортировать (только через админку)

Фикстуры НЕ входят в seed (`scripts/seed/data/` не содержит их;
`V2__demo_data.sql` не трогался). Единственный путь в БД — импорт
администратором:

1. поднять стек (`docker compose up` или локально
   PostgreSQL + backend + frontend + seed);
2. войти как `admin`;
3. «Админка» → «Импорт каталога» → выбрать файл →
   «Загрузить» (или `POST /api/admin/catalog/import` с токеном админа);
4. в summary — 4 решения и 108 характеристик на файл; повторная
   загрузка того же файла — 0 добавлений.

Автоматическая проверка на живом стеке:

```bash
FRONTEND_URL=http://localhost:3000 python3 scripts/verify_fixtures.py
```

24 проверки: импорт обоих наборов через BFF админки + UI-форма,
идемпотентность, публичный каталог, полный путь (проект → параметры →
подбор → сценарий → экономика → имитация → экспорт SVG/PDF),
рендер страницы имитации.

Снапшоты фикстур для юнит-тестов —
`backend/src/test/resources/test-fixtures/` (сверяются с этим каталогом
байт-в-байт в `CatalogImporterTest`, как снапшот полного каталога
организатора).
