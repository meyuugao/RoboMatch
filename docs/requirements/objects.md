# Объекты и входные параметры

## Требования

### Типы объектов
> В рамках хакатона необходимо обеспечить работу платформы для одного из трех базовых типов объектов: склада, аэропорта и медицинского учреждения — или же для другого типа объектов на выбор участников. Архитектура данных и расчетных модулей должна допускать добавление новых отраслей, объектов и типов роботизированных решений без переработки ядра системы.

> Необходимо показать работу с тремя базовыми типами объектов хотя бы на уровне выбора, входных параметров и доступных решений.

### Параметры объектов
> Для каждого типа объекта должен быть предусмотрен отдельный набор обязательных и дополнительных параметров. Команда может расширить состав полей, если это повышает точность расчета и не усложняет базовый пользовательский путь.

**Таблица параметров:**

| Тип объекта            | Минимальный состав параметров                                                                                                                                                                                                                                                                                     |
|------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Склад                  | площадь и рабочие зоны; режим работы; объем входящих, внутрискладских и исходящих операций; тип хранения; количество SKU; средняя масса и габариты грузовой единицы; численность и стоимость персонала; производительность текущего процесса; протяженность маршрутов; доступная площадь и ограничения планировки |
| Аэропорт               | тип и зона операции; режим работы; пассажиро- или грузопоток; количество операций и пиковая нагрузка; протяженность маршрутов; масса и габариты перемещаемых объектов; численность персонала; требования безопасности; наличие закрытых и открытых зон                                                            |
| Медицинское учреждение | тип учреждения; площадь и этажность; режим работы; количество перевозок грузов, белья, питания, медикаментов или отходов; маршруты и лифты; требования к санитарной обработке; численность персонала; ограничения доступа и безопасности                                                                          |

### Ввод и импорт
> Поддержать ручной ввод данных через формы.

> Поддержать загрузку параметров из Excel или CSV по предоставленному шаблону.

### Валидация
> Проверять корректность типов, единиц измерения, обязательных полей и диапазонов значений.

### Значения по умолчанию и источники
> Отображать значения по умолчанию и источник каждого норматива.

### Расширяемость справочников
> Предусмотреть расширяемую структуру справочников для добавления новых типов объектов и параметров.

### Инфраструктурные параметры
> В демонстрационных датасетах для складов, аэропортов и медицинских учреждений могут присутствовать поля, описывающие: ровность пола; допустимый уровень шума и требования к акустике; доступность и мощность зарядной инфраструктуры; другие характеристики объекта.

## Что следует для реализации
- Пользователь выбирает тип объекта (склад, аэропорт, медучреждение). Отрасль не выбирается: она часть каталога, а не объекта; маппинг — `assumptions.md` §1.
- Модель `Object` с полем `type` (склад, аэропорт, медицина, другое).
- Для каждого типа — свой набор параметров (обязательные + дополнительные).
- Полный расчёт и имитация — только для склада.
  Для аэропорта и медицины — выбор объекта, параметры и решения
  (согласовано с `docs/mvp_scope.md`).
- Параметры хранятся в справочнике, редактируются через админку.
- Ручной ввод через формы с валидацией (типы, единицы, диапазоны, обязательные поля).
- Импорт из Excel/CSV по шаблону.
- Значения по умолчанию и источник норматива отображаются.
- Инфраструктурные параметры (пол, шум, зарядка) могут быть в датасете или задаваться допущениями.
- При неполноте данных — явные допущения в `assumptions.md`.
- Параметры объекта попадают в отчёт.
