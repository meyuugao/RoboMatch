# RoboMatch

Платформа предынвестиционной оценки роботизации склада: каталог решений
с ТТХ и ценами, подбор под параметры объекта, расчёт экономики трёх
сценариев (текущий процесс / покупка / роботы как услуга), 2D-имитация
с KPI и экспорт отчётов (PDF / Excel / CSV). Гостевой демо-расчёт -
без регистрации.

| Что | Как |
|---|---|
| Веб-интерфейс | http://localhost:3000 |
| REST API + Swagger UI | http://localhost:8080/swagger-ui.html |
| Каталог (открыт гостю) | http://localhost:3000/catalog |
| Гостевой демо-расчёт | http://localhost:3000/demo |
| Админка БД (Adminer) | http://localhost:8081 (db / postgres / postgres) |

## Быстрый старт (Docker)

Требуется только Docker. Свободные порты: 3000, 8080, 8081, 5432.

```bash
cp .env.example .env
# JWT_SECRET обязателен: плейсхолдер change-me… отклоняется при старте
# (fail-fast). Сгенерируйте реальный секрет:
sed -i "s|^JWT_SECRET=.*|JWT_SECRET=$(openssl rand -base64 48 | tr -d '\n')|" .env

docker compose up -d --build
```

- Первый запуск собирает образы (Gradle и Next.js внутри контейнеров) -
  это несколько минут; дальше кэш слоёв ускоряет пересборку.
- Порядок готовности: `db` healthy → `backend` healthy (Flyway применяет
  схему БД V1–V7, 31 таблица) → `seed` загружает полный каталог
  (187 решений из таблицы организатора + справочники + демо-аккаунты;
  контейнер завершается с кодом 0 - **это норма**) → `frontend`.
- Linux-хост: файловые хранилища `./data/*` должны принадлежать
  пользователю 1001 (backend работает non-root):
  `sudo chown -R 1001:1001 data/` (Docker Desktop сам решает права).

### Чек-лист «что должно подняться»

- [ ] `docker compose ps`: db и backend - **healthy**; seed - **Exited (0)**.
- [ ] http://localhost:3000 - главная страница.
- [ ] http://localhost:3000/catalog - каталог, ~187 карточек с ценами.
- [ ] http://localhost:3000/demo - гостевой демо-расчёт (без входа).
- [ ] http://localhost:8080/api/solutions - JSON, 200.
- [ ] http://localhost:8080/swagger-ui.html - Swagger UI, кнопка Authorize.
- [ ] http://localhost:8081 - Adminer (сервер `db`, postgres/postgres).
- [ ] Вход демо-аккаунтом: http://localhost:3000/login → `user`/`useruser`.

### Обновили код (git pull) - пересоберите образы

`docker compose up` **не пересобирает** уже собранные образы: после
`git pull` запускайте

```bash
docker compose up -d --build
```

иначе контейнеры поедут на устаревшем коде из ранее собранных образов.
Полный сброс вместе с данными: `docker compose down -v && docker
compose up -d --build`. Повторный `up` прогоняет seed заново - он
идемпотентен (обновляет те же строки, дублей не создаёт; пароли
демо-аккаунтов не сбрасывает).

## Роли и демо-аккаунты

| Роль | Логин / пароль | Возможности |
|---|---|---|
| Гость | без входа | каталог и сравнение решений; демо-расчёт на /demo (в памяти, ничего не сохраняется) |
| Пользователь | `user` / `useruser` | проекты, параметры, подбор, экономика, имитация, экспорт |
| Администратор | `admin` / `adminadmin` | всё выше + раздел «Управление» (каталог, справочники, импорт) |

Регистрация создаёт обычного пользователя; роль администратора
выдаётся только сидом.

После сида у `user` готовы демонстрационные проекты: «Демо: Оптимальный
склад», «Демо: Пиковая нагрузка - успех», «Демо: Умеренный масштаб»
(составы появляются после импорта тестовых фикстур - см. ниже) и
технологические проекты «E2E: *» с рассчитываемой экономикой.
Расчёты/имитации/экспорты запускаются кнопками в UI.

## Проверка функциональности (чек-лист)

Полные требования - в `docs/requirements/*.md` (выжимки конкурсного
задания). Ниже - быстрый путь проверки руками.

### Гость

- [ ] **Каталог без входа**: /catalog - поиск (подстрока в названии),
      фильтры (тип/подтип/отрасль/процесс/статус/УГТ/цена/грузоподъёмность),
      сортировка, пагинация. Ссылка с фильтрами делится целиком
      (состояние - в URL).
- [ ] **Детальная карточка**: клик по решению - полные ТТХ с источником
      каждого значения, кейсы применения.
- [ ] **Сравнение**: чекбоксы «Добавить к сравнению» (до 10) →
      «Сравнить (N)» → таблица по унифицированным характеристикам.
- [ ] **Демо-расчёт**: /demo → тип «Склад» (прочие - «скоро») →
      предзаполненные параметры демо-набора → «Показать демо-расчёт» →
      сравнение трёх сценариев с CAPEX/OPEX/окупаемостью; пометка
      «не сохраняется». Гость с /projects попадает на /login.

### Пользователь (`user`/`useruser`)

- [ ] **Проект**: «Новый проект» → имя, тип объекта «Склад» → карточка.
      Копирование и удаление (вместе с данными) - на карточке.
- [ ] **Параметры объекта**: формы с валидацией и подсказками,
      дефолты датасета, источник каждого параметра. Импорт Excel/CSV,
      шаблон XLSX, вложения (до 10 МБ).
- [ ] **Подбор**: «Запустить подбор» → статусы
      годится/требует проверки/исключено, Score и вклад каждого
      критерия (объяснимость), причины исключения.
- [ ] **Ручное добавление**: добавить в сценарий решение вне подборки -
      с причиной; дубликат в сценарии отклоняется.
- [ ] **Сценарии**: base (текущий процесс), покупка, RaaS; состав
      покупателя редактируется.
- [ ] **Экономика**: «Рассчитать и перейти к дашборду →» - все три
      сценария; таблица сравнения (CAPEX, OPEX, Δ, годовой эффект,
      окупаемость с интерпретацией, ROI, TCO); блок «Формулы и
      допущения»; чувствительность (3 параметра × 5 шагов);
      ручная корректировка метрики (новая версия расчёта, журнал
      изменений); история расчётов с версиями данных; редактор
      допущений проекта.
- [ ] **Имитация 2D**: запуск → SVG-схема склада (зоны, маршрут,
      роботы), управление (пауза/скорость 0,5–5×), 6 KPI + загрузка
      зон, сверка с расчётом экономики; «Сохранить схему (SVG)»;
      тёмная тема схемы - на лету.
- [ ] **Экспорт**: /export - PDF (10 разделов, оглавление, встроенная
      2D-схема), Excel (7 листов), CSV (UTF-8 BOM, «;»); выбор темы
      схемы в PDF; история выгрузок со скачиванием и удалением;
      пометка «предварительная оценка» на титуле.
- [ ] **Изоляция**: проект другого пользователя неотличим от
      несуществующего (404).

### Администратор (`admin`/`adminadmin`)

- [ ] **Раздел «Управление»**: виден только роли admin (гость → /login,
      пользователь → сообщение о правах).
- [ ] **Решения каталога**: список с поиском и фильтром «требуют
      проверки», создание/правка/удаление; массовое выделение и
      удаление со сводкой (занятые решения отклоняются с причиной).
- [ ] **ТТХ с провенансом**: редактор характеристик решения -
      источник, дата, подтверждённость.
- [ ] **Справочники** (7): CRUD, занятые записи не удаляются (409).
- [ ] **Импорт таблицы каталога**: файл CSV/XLSX (до 50 МБ, 15 колонок
      + ТТХ) → итоги импорта; повторный импорт того же файла -
      0 добавлений (идемпотентность).
- [ ] **Обновление по запросу**: повтор импорта последнего сохранённого
      файла одной кнопкой; журнал загрузок с итогами.

### Нефункциональное

- [ ] **Тёмная тема**: переключатель в шапке (светлая/тёмная/системная),
      все страницы включая каталог и демо-расчёт.
- [ ] **Разрешение 1366×768**, русскоязычный интерфейс.
- [ ] **Swagger UI**: Authorize → вставить JWT из
      `POST /api/auth/login` (поле `token`) → защищённые вызовы из UI.
- [ ] **Лимиты**: вложение > 10 МБ → 413 с понятным сообщением;
      файл каталога > 50 МБ → 413.

## Демо-данные и фикстуры

- Каталог сидируется из таблицы организатора
  (`docs/source/catalog_export_v4.csv`): 187 решений.
- **Тестовые фикстуры** `docs/test-fixtures/` (два файла: XLSX и CSV,
  по 4 решения с полными 27 ТТХ): загрузите через
  «Управление → Импорт каталога», чтобы получить полный путь без

  Импорт идемпотентен.

## Запуск без Docker

```bash
# 1) БД: docker compose up -d db  (PostgreSQL 16, схема применится Flyway'ем)
# 2) Backend (JDK 21):
cd backend
JWT_SECRET='dev-secret-0123456789-0123456789-0123456789' ./gradlew bootRun
# 3) Каталог (python 3.12+):
DATABASE_URL='postgresql+psycopg2://postgres:postgres@localhost:5432/robomatch' \
  python scripts/seed/run.py
# 4) Frontend (Node 20+):
cd frontend && npm install && npm run dev
```

## Диагностика

| Симптом | Причина и решение |
|---|---|
| `docker compose up` не стартует: «Задайте JWT_SECRET» | Скопируйте `.env.example` → `.env` и сгенерируйте секрет (`openssl rand -base64 48`) - плейсхолдер отклоняется намеренно |
| После `git pull` контейнеры на старом коде | `docker compose up` не пересобирает образы: `docker compose up -d --build` |
| Контейнер seed «Exited (0)» | Норма: одноразовый загрузчик каталога завершился успешно |
| seed завершился с ошибкой | `docker compose logs seed` - стек ошибки и строка «окружение: …» |
| Загрузки вложений падают по правам (Linux) | `sudo chown -R 1001:1001 data/` - backend работает от uid 1001 |
| Каталог пуст, хотя seed прошёл | Проверьте `docker compose logs backend`: Flyway должен применить V1–V7 до старта |
| 401 на всех API в Swagger | Нажмите Authorize и вставьте JWT из `POST /api/auth/login` |
| Полный сброс окружения | `docker compose down -v && docker compose up -d --build` |
